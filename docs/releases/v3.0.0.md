## Overview

Version 3.0.0 brings an expanded, reproducible validation baseline to the GPS-denied UAV swarm research platform. It strengthens local firmware-admission policy, protects the navigation fusion state from invalid metadata, improves estimator regression coverage, and repairs cross-platform build, workflow, packaging, and software-bill-of-materials (SBOM) validation.

The existing platform architecture remains centered on a **C++20 onboard autonomy and sensor-fusion runtime**, **visual-inertial and UWB/TDOA localization**, **peer/swarm coordination**, a **Go supervisory control plane**, and a **Python/PySide6 operator dashboard**. Local autonomy and immediate safety are designed to remain on the vehicle, rather than depend on a continuous backend connection.

## New additions and security hardening

### Firmware trust and anti-rollback admission

- Enforces non-blank signing-secret and trusted-signer configuration for hardened `field` and `production` profiles.
- Rejects startup when a previously accepted firmware state cannot be persisted.
- Validates firmware-version and rollback-counter regressions independently.
- Adds **17 reviewer-focused firmware-admission test cases** covering signer policy, keyed-digest mismatch, boot-condition claims, measurement metadata, maintenance-token presence, configuration errors, state-persistence failure, and accepted-state invariants.
- Verifies that rejected candidates leave the previously accepted state record unchanged.
- Documents the different `lab` profile behavior and the fact that a nonempty maintenance token proves **presence only**, not authorization.

This is an **application-level policy gate over supplied manifest metadata**. It does not independently hash installed firmware, validate a standardized digital signature, implement a hardware root of trust, or provide protected rollback-resistant storage.

### GPS-denied localization and estimator validation

- Fails closed when localization inputs contain non-finite metadata, including anchor-visibility or time-synchronization confidence values.
- Adds dedicated localization regression tests for degraded/lost state behavior.
- Improves MSCKF camera-state marginalization, deterministic track retirement, retained-covariance and cross-covariance checks, and invalid-state handling.
- Strengthens visual-feature ingestion and deterministic replay validation while retaining separation between active and shadow estimators.

## Bug fixes and build improvements

- Repairs C++ build/link, formatting, static-analysis, and workflow validation failures across GCC, Clang, and MSVC targets.
- Improves Python formatting and static-analysis compliance and C++ CodeQL validation.
- Corrects Linux Nightly GCC 13 strict-build handling for a `fmt` system-header `array-bounds` diagnostic; other project warning checks remain strict.
- Corrects CPack archive collection, including `.tar.gz` output, and downstream package-consumer verification.
- Adds a compatible Go toolchain for pinned Syft SBOM generation while retaining the application's Go 1.22 module requirement.
- Validates generated CycloneDX SBOM files and verifies SHA-256 checksums of regular output files, excluding CPack staging directories and the checksum manifest itself.
- Adds pull-request validation of changes to the Nightly workflow itself.
- Updates the README landing section and sets the CMake/CPack **project version to 3.0.0**.

## Upgrade and compatibility notes

The `field` and `production` firmware-admission profiles now reject a missing or whitespace-only secret, an empty trusted-signer allowlist, and reported failures to save the accepted-state record. Users upgrading permissive research configurations should review trusted-signer configuration, secret provisioning, and state-file write permissions before starting a hardened profile. Laboratory mode remains separately scoped.

CMake/CPack now reports project version **3.0.0**. Record the exact Git commit, toolchain, settings, and test fixtures when reproducing software experiments.

## Known limitations

- Hardware-backed secure boot, measured-boot integrity, standardized firmware digital-signature verification, and privileged-tamper resistance have **not** been established.
- Maintenance-token presence is **not** authenticated operator approval. The local accepted-state file is neither crash-atomic nor hardware rollback-resistant.
- The shadow visual estimator has **not** been granted automatic flight-control authority.
- Completed physical HIL, production-radio, multi-UAV flight validation, autonomous free-flight qualification, and airworthiness certification are **not claimed**.
- CI and replay/simulation results must not be presented as measured physical-flight performance.
